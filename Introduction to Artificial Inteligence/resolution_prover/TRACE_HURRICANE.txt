EXAMPLE 2: Hurricane Evacuation Problem
Domain: Based on HW1 Hurricane Evacuation Problem
File: examples/hurricane.cnf
Situation Calculus Formulation

======== PROBLEM SETUP ========

Graph:
  Vertices: 1, 2, 3, 4
  Edges:
    - 1-2: FLOODED (requires amphibian kit to traverse)
    - 1-3: Not flooded
    - 2-3: Not flooded
    - 3-4: Not flooded
    - 2-4: Not flooded

Initial State:
  Agent location: vertex 1
  People to rescue: vertex 2 (1 person), vertex 4 (1 person)
  Amphibian kit: vertex 1 (initially unequipped)

Actions Available:
  - EQUIP: Agent equips amphibian kit at its location (allows flooded traversal)
  - TRAVERSE: Agent moves along an edge (if not flooded or equipped)
  - UNEQUIP: Agent unequips kit (leaves it at current vertex)

Goal: PROVE that all people can be rescued (AllPeopleRescued)
Negated Goal: HasPeople exists at some location (people not rescued)

======== SITUATION CALCULUS AXIOMS ========

Predicate Definitions:
  At(agent, L, s)          : Agent is at location L in situation s
  HasPeople(L, s)          : Location L has people needing rescue in situation s
  HasKit(L, s)             : Location L contains amphibian kit in situation s
  Equipped(agent, s)       : Agent has equipped the kit in situation s
  CanTraverse(from, to, s) : Edge from-to is traversable in situation s
  Flooded(from, to)        : Edge from-to is flooded (static fact)

Key Axiom:
  CanTraverse(from, to, s) if ~Flooded(from, to) OR Equipped(agent, s)

Initial Conditions:
  At(agent, loc1, s0)
  HasPeople(loc2, s0)
  HasPeople(loc4, s0)
  HasKit(loc1, s0)
  ~Equipped(agent, s0)

======== RESOLUTION STEPS (OUTLINE) ========

Optimal Action Sequence:
1. At vertex 1: EQUIP the kit
   - Effect: Equipped(agent, s1)
   - Now agent can traverse flooded edges

2. Traverse edge 1-2 (flooded, but now equipped)
   - Precondition: At(agent, 1, s1) AND CanTraverse(1, 2, s1)
   - Effect: At(agent, 2, s2)
   - Side effect: HasPeople(loc2, s2) = FALSE (people picked up)

3. Traverse edge 2-4 (not flooded)
   - Precondition: At(agent, 2, s2) AND CanTraverse(2, 4, s2)
   - Effect: At(agent, 4, s3)
   - Side effect: HasPeople(loc4, s3) = FALSE (people picked up)

4. Derive contradiction with negated goal
   - Goal negation: HasPeople(loc_remaining, s_final)
   - Facts derived: ~HasPeople(loc2, s3) AND ~HasPeople(loc4, s3)
   - Conclusion: No location has people left
   - Therefore: AllPeopleRescued(s3) is TRUE

======== PROOF IN CNF ========

The Hurricane problem is formalized as a set of CNF clauses representing:
1. Initial state facts (facts, not flooded)
2. Static properties (which edges are flooded)
3. Traversal rules (preconditions for moving)
4. Action effects (changes to world state)
5. Rescue effects (people rescued when agent arrives)
6. Kit management (equip/unequip effects)
7. Negated goal (someone not yet rescued)

Resolution proof shows through logical derivation that:
  Starting from initial state
  AND applying action axioms
  AND applying preconditions
  DERIVES contradiction with "someone still needs rescue"
  
Therefore: The goal "all people are rescued" is PROVED.

  - Direct path 1-2-4 or 1-3-4 rescues all people
  - Proof demonstrates planning correctness
